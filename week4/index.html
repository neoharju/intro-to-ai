Neural networks: from a decision boundary to learned representations

A neural network is a parameterized function built by composing simpler functions. Training changes its parameters so that its outputs become useful for a task. The central questions this week are: what can a network represent, how can its parameters be learned, and how do we know that it has learned something useful beyond the training examples? We will follow one example, recognizing handwritten digits, and use small numerical examples to make the computations visible.

The word neuron is a mathematical analogy, not a claim that these models reproduce a biological brain. A network's architecture, training objective and data determine what it can learn. Large parameter counts alone do not explain intelligence, understanding or reliable behaviour.

From perceptrons to learning

Historical context: an old idea, several different research traditions

Neural networks did not begin with today's large language models. They emerged from attempts to connect mathematical models of computation, learning and nervous systems. The history includes logical threshold units, trainable classifiers, associative memories, self-organizing maps and deep representation learning. These traditions overlap; they are not a simple sequence in which each new model replaces everything before it.

The broader narrative is developed in Goodfellow, Bengio and Courville (2016), Chapter 1.

The brain analogy: copy an organizing idea, not a whole brain

The useful analogy is that many connected units can produce complex behaviour, and changing their connections can change that behaviour. A biological neuron is a living cell with dendrites, a cell body and an axon. Signals arriving through synapses affect its activity; many neurons transmit action potentials along the axon and communicate chemically at synapses. The artificial unit keeps only a small part of this picture: inputs, adjustable connection weights, an aggregation and an output function.

Brains contain extensive recurrent connections, many cell types and interactions over multiple timescales. Artificial networks may be feedforward, recurrent, probabilistic or spiking. Consequently, “natural networks are binary while artificial networks are continuous” and “artificial networks have no feedback” are not universal distinctions. A spike is an event, but firing rates, spike timing and other biological variables also carry information.

Connection to computation: parallel, adaptive neural computation contrasts with the simple picture of a sequential instruction-following program, but it does not establish that neural networks compute functions outside the Turing-computable class. Most networks in this course run as numerical programs on conventional digital hardware. Brain inspiration also supplies no automatic evidence of consciousness or human-like understanding.

Historical extension: associative memory and self-organizing maps

A Hopfield network provides an example of recurrent dynamics: its evolving state can retrieve a stored pattern from a partial or corrupted cue. Under suitable conditions, an energy function helps analyze convergence; this does not mean every cue retrieves the intended memory. A Boltzmann machine uses stochastic units in an energy-based probabilistic model. A self-organizing map uses a different idea: a winning prototype and neighbouring prototypes move toward an input, organizing a grid by similarity. These examples show why neural computation encompasses more than supervised feedforward classification. They provide context, not additional implementation requirements this week.

What does the network actually receive?

A handwritten digit image might contain 28 by 28 grayscale pixels. A fully connected network can receive it as a vector of 784 numbers. A pixel value is a measurement, not an instruction such as “this is the upper loop of an eight.” The model must learn which combinations of measurements are useful. A training example pairs an input x with a target y, such as the digit label 8.

A training dataset contains many such pairs. At prediction time the model receives a new image without the correct label. Its parameters must therefore encode a rule that works across variations in handwriting, thickness and position, rather than a lookup table for images it has already seen. Features such as pixel scale and image resolution must be consistent between training and later use.

Preprocessing: MNIST pixels usually range from 0 to 255. Dividing by 255 maps them to the interval [0, 1]. For other numeric features, standardization may help optimization. Fit any data-dependent preprocessing on the training split only. The input representation and preprocessing are part of the model pipeline.

The perceptron as an adjustable decision boundary

A perceptron computes a weighted sum z and adds a bias. We use the convention that the prediction is 1 if z \ge 0 and 0 otherwise:

z = w_1 x_1 + \dots + w_d x_d + b = w \cdot x + b, \qquad \hat{y} = \begin{cases} 1 & \text{if } z \ge 0, \\ 0 & \text{otherwise.} \end{cases}

Each weight controls how one input contributes to the score. The bias is an adjustable offset. The classification boundary consists of inputs for which z = 0: a line in two dimensions, a plane in three, and a hyperplane in higher dimensions.

Worked prediction: let x = (1, 2), w = (0.7, -0.2) and b = 0.1. The score is 0.7 \times 1 - 0.2 \times 2 + 0.1 = 0.4, so the output is 1. A negative weight does not make an input unimportant: it makes increasing that input lower the score, holding other inputs fixed.

For two inputs, changing the weights changes the orientation and location of the line. Changing only the bias shifts the boundary parallel to itself. The model learns these quantities from examples rather than asking a programmer to draw the line by hand.

A concrete learning update

The generalized error-correction form makes the learning rule easy to remember. Using the same notation as the lecture slides, the perceptron learning rule is

w' = w + \lambda\,(y - \hat{y})\,x, \qquad b' = b + \lambda\,(y - \hat{y})

Here w is the current weight vector, w' the updated vector, x the current input, y the true label, \hat{y} the predicted label, and \lambda > 0 the learning rate. Each component follows w_i' = w_i + \lambda\,(y - \hat{y})\,x_i. A correct prediction gives zero error, so no update. A mistake changes the parameters in the direction that supports the target label.

Here we use labels 0 and 1, so the error term is −1, 0 or +1. The same written formula also works with labels −1 and +1, but an incorrect prediction then gives −2 or +2. Its step size therefore depends on the label convention as well as \lambda. The familiar signed-label update w' = w + \alpha\, y\, x on a mistake is equivalent when \alpha = 2\lambda.

Suppose the correct label for the example above is 0 and \lambda = 0.1. The error term is −1. The new weights are (0.6, -0.4) and the new bias is 0. The score for that same example becomes 0.6 - 0.8 = -0.2, which gives class 0. This fixes this example; it does not guarantee that all other examples are now correct. Training revisits the dataset, allowing different examples to influence the boundary.

Check your understanding: one more update

With w = (0, 0), b = -0.5, x = (1, 1), target 1 and \lambda = 0.5, the initial score is −0.5 and the prediction is 0. The new weights are (0.5, 0.5), the bias is 0 and the score becomes 1. Notice that the update changes the bias as well as the weights.

Reading: Rosenblatt's original perceptron paper (1958) supplies historical context. The numerical examples here use a simplified modern notation.

Worked example with −1/+1 labels, as in the lecture slides

Use \hat{y} = +1 when w \cdot x \ge 0 and −1 otherwise. For this illustration only, omit the bias and start at w = (0, 0). The score is initially zero for every input, so every input receives +1. This is a degenerate classifier, not a meaningful separating line.

  1. For A = (-2.5, -1) with target −1 and \lambda = 1, y - \hat{y} = -2. Therefore w' = (0, 0) + 1 \cdot (-2) \cdot (-2.5, -1) = (5, 2).
  2. For B = (1, -2) with target −1, the new score is 5 - 4 = 1, so the prediction is again +1. Update to w'' = (5, 2) + 1 \cdot (-2) \cdot (1, -2) = (3, 6).
  3. For C = (-2, 1) with target −1, the score is -6 + 6 = 0, giving +1. Keeping \lambda = 1 gives w''' = (3, 6) + 1 \cdot (-2) \cdot (-2, 1) = (7, 4).

Alternatively, starting again from (3, 6) for that third update and choosing \lambda = 0.5 gives (5, 5). These are two different learning-rate choices, not the same update. For a general affine boundary, include the bias update above. Equivalently, append a constant input 1 and treat the bias as its weight.

This is a perceptron error-correction rule, not a universal training formula for every neural network. In a sigmoid output with binary cross-entropy, a single-example gradient update also has an error-times-input form when \hat{y} denotes a probability. Hidden layers additionally require the derivatives calculated by backpropagation.

Why one neuron cannot solve XOR

The perceptron learning rule converges to a separator after finitely many errors when a finite dataset is linearly separable and the usual assumptions of the convergence theorem hold. When the classes overlap or require a nonlinear boundary, there may be no separating weights to find. More training cannot repair a limitation of the model family.

Multilayer networks and forward propagation

A multilayer perceptron (MLP) alternates affine transformations and nonlinear activation functions. In layer \ell,

z^{(\ell)} = W^{(\ell)} h^{(\ell-1)} + b^{(\ell)}, \qquad h^{(\ell)} = \varphi\bigl(z^{(\ell)}\bigr),

with h^{(0)} = x. Each hidden layer provides a representation for the next layer. The output layer converts the final representation into the quantities required by the task.

Keep track of dimensions: a digit classifier with 784 inputs, 40 hidden units and 10 outputs has a first weight matrix of shape 40 \times 784, a bias vector of length 40, a second matrix of shape 10 \times 40 and an output bias vector of length 10. It contains 784 \times 40 + 40 + 40 \times 10 + 10 = 31{,}810 trainable parameters. The input layer stores data and does not add trainable weights of its own.

Small forward pass: let x = (1, 2), with first-layer weights W_1 and bias b_1 = (0, -0.5). The pre-activations are (-1, 1), and ReLU produces the hidden vector (0, 1):

z = W_1 x + b_1 = \begin{bmatrix} 1 & -1 \\ 0.5 & 0.5 \end{bmatrix} \begin{bmatrix} 1 \\ 2 \end{bmatrix} + \begin{bmatrix} 0 \\ -0.5 \end{bmatrix} = \begin{bmatrix} -1 \\ 1 \end{bmatrix}, \qquad h = \operatorname{ReLU}(z) = \begin{bmatrix} 0 \\ 1 \end{bmatrix}

With output weights (2, -1) and output bias 0.5, the output score is 2 \times 0 - 1 \times 1 + 0.5 = -0.5. The sigmoid of that score is approximately 0.378. No learning occurred in this calculation: it is one evaluation using the current parameters.

Increasing width adds units within a layer. Increasing depth adds transformations that can reuse earlier representations. Neither guarantees better test performance. Some functions admit much more compact deep representations, but data, training stability and architecture still matter. Hidden units need not correspond to concepts that are easy for humans to name.

Why nonlinear activations are essential

Two affine layers without a nonlinearity collapse into one:

W_2 (W_1 x + b_1) + b_2 = (W_2 W_1)\, x + (W_2 b_1 + b_2)

Adding more such layers therefore does not overcome the perceptron's linear representational limitation. A nonlinear activation changes the kinds of functions that the composition can express. The common choices are

\sigma(z) = \frac{1}{1 + e^{-z}}, \qquad \tanh z = \frac{e^{z} - e^{-z}}{e^{z} + e^{-z}}, \qquad \operatorname{ReLU}(z) = \max(0, z)

Hidden activations and output functions need not be the same. A regression model may use an unrestricted numeric output. Binary classification often uses a sigmoid. For ten mutually exclusive digit classes, softmax converts ten scores, or logits, into nonnegative values summing to 1. A large softmax value can still be wrong or poorly calibrated; it is not a guarantee of correctness.

\operatorname{softmax}(z)_k = \frac{e^{z_k}}{\sum_{j=1}^{10} e^{z_j}}, \qquad k = 1, \dots, 10

What is the network trying to minimize?

A loss function measures how the output differs from the target. For a scalar regression example with prediction \hat{y} we can use L = (\hat{y} - y)^2 / 2. For binary classification, cross-entropy penalizes low probability p assigned to the correct label:

L = -\bigl[\, y \log p + (1 - y) \log (1 - p) \,\bigr]

For multiclass classification with one correct class, the corresponding loss is -\log p_{\text{correct}}.

If the correct class receives probability 0.8, the multiclass loss is approximately 0.223. At probability 0.2 it is approximately 1.609. This distinguishes two predictions even when both choose the same top-ranked class. Accuracy counts correct classifications, while loss provides a graded learning signal. In practical libraries, cross-entropy often accepts logits and combines the output transformation and logarithm in a numerically stable operation.

The objective usually averages losses over examples, possibly with a regularization term. It is a design choice. Poor labels or a poorly chosen objective can produce a model that optimizes the training task without serving the intended real-world purpose.

Backpropagation: calculating which changes would reduce loss

A gradient reports how sensitive the loss is to a small change in a parameter, with other parameters held fixed. A positive derivative means increasing that parameter would locally increase the loss. Gradient descent therefore makes an update in the opposite direction, with learning rate \eta:

\theta \leftarrow \theta - \eta\, \nabla_\theta L

This is a local calculation, not a guarantee of the best possible network.

Backpropagation efficiently computes gradients by applying the chain rule through the computation graph. It reuses intermediate results from the forward pass and propagates sensitivities backward. The optimizer then uses the gradients to update parameters. Backpropagation and gradient descent are different operations, even though both occur during training.

A complete numerical backward pass

Consider a deliberately tiny network with one hidden unit: z = wx + b, h = \operatorname{ReLU}(z), prediction \hat{y} = vh + c and L = (\hat{y} - y)^2 / 2. Let x = 2, y = 1, w = 0.5, b = 0, v = 2 and c = 0. The forward pass gives z = 1, h = 1, prediction 2 and loss 0.5.

With learning rate 0.1, update all four parameters using these gradients: w = 0.1, b = -0.2, v = 1.9 and c = -0.1. A new forward pass gives z = 0, h = 0, prediction −0.1 and loss 0.605. The loss increased: the first-order approximation did not justify so large a step, and the hidden unit reached the ReLU boundary.

Repeat from the original parameters with learning rate 0.01 instead. We obtain w = 0.46, b = -0.02, v = 1.99 and c = -0.01. Then h = 0.9, prediction 1.781 and loss approximately 0.305. A gradient gives a local direction; choosing a suitable step size is essential.

Activity: trace the backward pass without a library

First ask which derivative contains the input x and why. Then ask what would happen to the gradient of w if z were strictly negative. Updating v before computing the derivative for w would mix two different networks in one backward pass.

Putting the training loop together

initialize parameters to small, non-identical random values
for each epoch:
    shuffle the training examples
    for each mini-batch:
        compute predictions with a forward pass
        compute the average loss
        compute gradients with backpropagation
        update parameters with the optimizer
    evaluate on validation data without updating parameters
select a checkpoint using validation results
evaluate the selected model on the test set

Random initialization breaks symmetry. If all units in a hidden layer start identically and receive identical updates, they may keep learning the same feature. Initialization schemes such as Xavier/Glorot and He initialization choose scales to help signals and gradients remain useful across layers. A random seed improves reproducibility, although some hardware and software operations can still vary.

Training, generalization and representation learning

Epochs, batches and optimizers

An epoch is one pass over the training examples. A mini-batch is a group used to estimate a gradient for one parameter update. With 6,000 training examples and batch size 100, one epoch normally contains 60 updates. Eight epochs contain about 480 updates, not eight. Training loss is often noisy because different batches contain different examples.

Full-batch gradient descent uses the entire training set for one update. Single-example stochastic gradient descent updates after every example. Mini-batches provide a practical compromise: efficient computation with a noisy approximation to the full gradient. A larger batch changes the optimization dynamics and resource use; it does not automatically give better generalization.

Learning rate: too small may make progress impractically slow; too large may overshoot or diverge, as the worked example showed. A schedule changes it over time. Momentum accumulates information from previous gradients. Adam maintains moving estimates of gradients and their squared values to adapt updates. No optimizer removes the need to inspect the data, loss and validation behaviour.

Training foundations moved earlier: these concepts were previously introduced among Week 5's Transformer details. They apply to ordinary networks too. Week 5 will build on them when discussing gradient accumulation, learning-rate schedules and large-scale training.

Learning the training set is not the same as learning the task

The training set supplies examples used to update parameters. The validation set supports choices such as model size, learning rate and stopping time. The test set estimates the performance of the selected pipeline. Repeatedly choosing architectures using test scores turns the test set into another validation set and can make the reported result optimistic.

For digit recognition, keep all copies or augmentations of one original image within the same split. In other applications, split by person, device or time when that matches the intended deployment. Randomly separating adjacent sensor readings may leak almost identical observations across splits. A high test score on one distribution does not establish robustness to a new camera or handwriting population.

These curves are illustrative, not measurements from an experiment. Underfitting means that the fitted model cannot capture the relevant training patterns well. Overfitting occurs when training performance improves without corresponding improvement on new data. Training loss decreasing while validation loss rises is a useful warning sign, not a universal diagnostic.

  • L2 regularization adds a penalty on squared weight magnitudes. Its strength is a hyperparameter.
  • Early stopping chooses a checkpoint based on validation performance rather than the lowest training loss.
  • Dropout randomly suppresses some activations during training. Prediction uses the corresponding inference-time convention rather than randomly dropping units in the same way.
  • Data augmentation creates plausible variations, such as small translations of digit images. A transformation that changes the correct label is unsuitable.

Regularization does not guarantee improvement, and a bigger model is not automatically overfit. Compare learning curves and repeat promising experiments across seeds. Report the data split, preprocessing and selection procedure along with accuracy. See Goodfellow, Bengio and Courville, Chapter 7 for a more detailed treatment.

Why images motivate convolutional networks

A fully connected layer treats every pixel position as a separate input connection. A small pattern, such as a stroke corner, may occur in many positions. A convolutional layer uses the same learned filter at different image locations. Local connectivity and shared weights encode a useful assumption: the same local pattern can matter wherever it appears.

A filter multiplies a small image patch element by element and sums the results, usually adding a bias. For the patch and the filter below, with zero bias, the result is 1 - 4 = -3:

\text{patch} = \begin{bmatrix} 1 & 2 \\ 3 & 4 \end{bmatrix}, \quad \text{filter} = \begin{bmatrix} 1 & 0 \\ 0 & -1 \end{bmatrix}: \quad 1 \cdot 1 + 2 \cdot 0 + 3 \cdot 0 + 4 \cdot (-1) = -3

Sliding the filter over a larger image produces a feature map. This common deep-learning operation is technically cross-correlation; software usually calls the layer a convolution.

Parameter comparison: an RGB filter with height 3 and width 3 has 3 \times 3 \times 3 + 1 = 28 parameters including its bias. Sixteen such filters have 448 parameters, regardless of the number of locations at which they are applied. The feature maps can still be large, so fewer parameters does not mean negligible computation or memory.

Stride controls how far the filter moves between locations. Padding adds a border to control output size. Pooling summarizes local neighbourhoods and reduces spatial resolution, while strided convolutions can also downsample. These operations can improve tolerance to small shifts, but a CNN is not automatically invariant to every translation, rotation or change in viewpoint.

A typical digit CNN learns several feature maps, combines them in later layers and produces class scores. Early filters may respond to simple strokes; later patterns can combine evidence from larger regions. This is an architectural bias, not a guarantee that each hidden unit has a clean human interpretation. Connection to Week 5: Vision Transformers use image patches and attention instead of relying on exactly this local-filter design. Understanding CNNs makes the contrast meaningful.

From discrete identifiers to learned embeddings

A word or token identifier is arbitrary. If “cat” has ID 12 and “dog” has ID 13, the neighbouring numbers do not make their meanings similar. A one-hot encoding avoids that false ordering but uses one coordinate per vocabulary item. An embedding table assigns each item a learned vector with a chosen dimension. Looking up a token selects one row of that table.

A vocabulary of 10,000 tokens with 50-dimensional embeddings contains 500,000 embedding parameters. The training task supplies the signal that moves those vectors. Context prediction, classification and recommendation can therefore learn different notions of similarity. Vectors do not receive their meaning from their coordinate names, and rotating the whole space can preserve its pairwise geometry.

For vectors u and v, cosine similarity is

\cos(u, v) = \frac{u \cdot v}{\lVert u \rVert\, \lVert v \rVert}.

For example, u = (1, 0) and v = (1, 1) have cosine similarity 1/\sqrt{2} \approx 0.707. A value close to 1 indicates similar directions, not necessarily that the words are interchangeable. Antonyms can share contexts and appear close together. Similarity is learned association, not a universal measure of meaning.

Static embeddings assign “bank” one vector even when it refers to a river bank or a financial institution. Contextual networks compute different representations for different occurrences. The drawing above is an illustration of a projection, not measured evidence that semantic categories occupy tidy two-dimensional clusters. Embeddings can also reflect biases or gaps in their training data.

Why sequence order changes the problem

“The dog chased the child” and “The child chased the dog” contain the same words but describe different events. Averaging static word embeddings loses this order. A recurrent neural network (RNN) processes a sequence by repeatedly updating a hidden state:

h_t = \tanh\bigl(W_x x_t + W_h h_{t-1} + b\bigr)

It shares parameters across positions, while the hidden state depends on the preceding inputs.

The state is a learned summary, not a perfect memory. Gradients through long sequences can become very small or large, making long-range dependencies difficult to learn. Gated architectures such as LSTMs and GRUs address parts of this problem, without eliminating every limitation. This is a conceptual introduction; implementing the gates is not required this week.

Bridge to attention: rather than forcing every relevant detail through one recurrent state, attention lets a representation combine information from selected positions. In Week 5, query–key scores will determine those combinations. Transformers also require positional information because a set of token vectors alone does not express sequence order. CNNs, RNNs and attention offer different assumptions about how information should be combined; they are not merely progressively larger versions of the same model.

Autoencoders: learning without class labels

Representation learning need not predict a class. An autoencoder maps an input to a code with an encoder, z = \operatorname{encoder}(x), then reconstructs it with a decoder, \hat{x} = \operatorname{decoder}(z). The training target is derived from the input rather than supplied as a digit category. A reconstruction loss measures the difference between the original and reconstructed data.

A bottleneck, denoising objective or another constraint can discourage trivial copying. For example, a 16-dimensional code must summarize a 784-dimensional image in a limited space. That code may retain stroke style as well as digit identity because both help reconstruction. It need not be the best representation for classification. A sufficiently flexible unconstrained network could instead learn an unhelpful identity mapping.

A standard autoencoder is not automatically a generator of realistic new images. Random points in its code space may decode poorly. Models such as variational autoencoders impose additional structure to support sampling. We introduce the encoder–decoder and latent-code ideas here, before Week 5's generative models. The existing graded autoencoder exercise remains in Week 5.

Training Your First Neural Network (programming) (1.5p)

Time to stop drawing perceptrons on paper and actually train one. We'll use scikit-learn's MLPClassifier, which hides the training loop (forward pass, loss, backward pass, weight update) behind a single .fit() call — exactly the same building blocks you've read about, just already wired up for you.

The complete setup below downloads MNIST, scales its pixels, fixes a 10,000-image subset and creates separate training, validation and test splits. The first download requires an internet connection. If you instead reuse the local data in Perceptron.zip, adapt the loading step and check its pixel encoding before scaling: the 6,000 images in mnist-x.data already have pixel values 0 and 1, so do not divide them by 255. Use the validation split for the comparisons below; reserve the test split for the final selected configuration: 

from sklearn.datasets import fetch_openml
from sklearn.model_selection import train_test_split
from sklearn.neural_network import MLPClassifier

# MNIST download is required on the first run. Use a fixed subset for speed.
X, y = fetch_openml("mnist_784", version=1, return_X_y=True, as_frame=False)
X = X.astype("float32") / 255.0
X_small, _, y_small, _ = train_test_split(
    X, y, train_size=10000, stratify=y, random_state=1
)
X_dev, X_test, y_dev, y_test = train_test_split(
    X_small, y_small, test_size=0.2, stratify=y_small, random_state=1
)
X_train, X_val, y_train, y_val = train_test_split(
    X_dev, y_dev, test_size=0.2, stratify=y_dev, random_state=1
)

clf = MLPClassifier(
    hidden_layer_sizes=(40,),   # one hidden layer, 40 neurons
    max_iter=8,
    solver="sgd",
    learning_rate_init=0.2,
    random_state=1,
)
clf.fit(X_train, y_train)
print("Validation accuracy:", clf.score(X_val, y_val))
# After choosing a configuration using validation results only:
# print("Final test accuracy:", selected_clf.score(X_test, y_test))
  1. Run the code above as-is and note the validation accuracy.
  2. Change hidden_layer_sizes=(40,) to (10,), then to (100, 50) (two hidden layers). Rerun each and record validation accuracy.
  3. Change max_iter=8 to 50 (keeping hidden_layer_sizes=(40,)) and rerun.
  4. In 3–4 sentences: which change helped most, which helped least or hurt, and does that match your intuition about network capacity vs. training time?
  5. Select a configuration using validation results, refit it with the same training split, and report its held-out test accuracy once. Do not use the test result to select another configuration.
What's actually happening inside .fit()?

With solver="sgd", max_iter=8 permits up to eight epochs, not eight parameter updates. Each epoch contains multiple mini-batches, each with a forward pass, loss calculation, backpropagation and an optimizer update. The splits above hold 6,400 training, 1,600 validation and 2,000 test images; with the default batch_size of 200 images, one epoch is 32 mini-batches and so 32 updates. The MLP learns hidden representations using gradients of the cross-entropy loss; the threshold perceptron instead uses its mistake-driven update rule, which can train only a single layer of weights. A convergence warning after only eight epochs can be expected and does not by itself mean that the code failed. Inspect learning progress, for example the training loss of each epoch in clf.loss_curve_, before drawing conclusions.

Backpropagation by hand: XOR in NumPy

MLPClassifier and Keras hide the training loop. The numerical backward pass above applied the chain rule to one hidden unit by hand. Here is the same computation in matrix form, for the XOR problem that a single perceptron cannot solve: two inputs, a hidden layer of four \tanh units, a sigmoid output and the cross-entropy loss. The notation follows the core material: each row of X is one example, and a weight matrix has one row per unit of its layer, so W1 has shape 4 × 2, like the 40 × 784 matrix of the digit network, and a layer computes Z = X W^\top + b. 

import numpy as np

X = np.array([[0, 0], [0, 1], [1, 0], [1, 1]], dtype=float)   # one example per row
Y = np.array([[0], [1], [1], [0]], dtype=float)               # XOR

def forward(W1, b1, W2, b2):
    H = np.tanh(X @ W1.T + b1)                  # hidden layer, shape (4, 4)
    P = 1 / (1 + np.exp(-(H @ W2.T + b2)))      # output probabilities, shape (4, 1)
    return H, P

def train(W1, b1, W2, b2, steps=5000, lr=0.5):
    for _ in range(steps):
        H, P = forward(W1, b1, W2, b2)
        # Backward pass: the chain rule, layer by layer
        G2 = (P - Y) / len(X)                   # dLoss/dZ2 for a sigmoid with cross-entropy
        dW2, db2 = G2.T @ H, G2.sum(axis=0)     # weight gradient: G^T times the layer's input
        G1 = (G2 @ W2) * (1 - H ** 2)           # back through W2, then tanh'(z) = 1 - tanh(z)^2
        dW1, db1 = G1.T @ X, G1.sum(axis=0)
        # Gradient descent step: the four examples form one batch
        W1 -= lr * dW1; b1 -= lr * db1; W2 -= lr * dW2; b2 -= lr * db2
    return W1, b1, W2, b2

rng = np.random.default_rng(1)
params = train(rng.normal(0, 1, (4, 2)), np.zeros(4), rng.normal(0, 1, (1, 4)), np.zeros(1))
H, P = forward(*params)
print(P.ravel().round(3))     # [0.    0.999 0.999 0.002]
print(H.round(2))             # the learned hidden representation, one row per input

The line G2 = (P - Y) / len(X) is worth a second look: for a sigmoid output with the cross-entropy loss, the derivative of the loss with respect to the output's logit is simply p - y, the prediction minus the target. This is the error-times-input form mentioned with the perceptron rule. Each layer then needs the two products of the extra section below: G2 @ W2 sends the error back to the hidden layer, and G1.T @ X gives the weight gradient. A framework like PyTorch derives the same products for you with automatic differentiation.

What the hidden layer learned

The XOR activity set two hidden units by hand: "at least one input is 1" and "both inputs are 1". Gradient descent found a different representation. With seed 1, the printed matrix H shows it: the second hidden unit is close to +1 only for the input (1, 0), the fourth only for (0, 1), and both are negative for the other inputs. The output weights, params[2], are largest for these two units (about 7 each), so the network computes XOR as "x_1 and not x_2, or x_2 and not x_1". The other two units are large and positive for any input that contains a 1, and they count less. Many hidden representations solve the same task; training finds one of them, and it need not be the one a person would design.

Why the starting point matters

Try two experiments with the code above. First, use only two hidden units, the size of the hand-set solution: change (4, 2), np.zeros(4) and (1, 4) in the last lines to (2, 2), np.zeros(2) and (1, 2). Two units can represent XOR, yet in our runs gradient descent solved it from only 52 of 100 random starts, and almost all of the other runs got stuck predicting about 0.5 for two of the four inputs (seed 0 is one of them). With three units, 84 of 100 runs succeeded; with four, 98; with eight, all 100. The extra units are not needed to represent the function, but they make it much easier to find. Second, start every weight at 0.5 instead of a random number. Now all hidden units compute the same thing and receive the same gradient, so they stay identical forever: the network behaves as if it had one hidden unit, and it cannot solve XOR. This is the symmetry that random initialization breaks, as described in Putting the training loop together.

What the universal approximation theorem says, and what it does not

A network with one hidden layer can approximate any continuous function on a bounded region as closely as you like, given enough hidden units: Cybenko (1989) proved this for sigmoids, and Leshno, Lin, Pinkus and Schocken (1993) for every continuous activation that is not a polynomial. It is often quoted as "neural networks can learn anything". It does not say that: it says nothing about how many units are needed (possibly astronomically many), whether gradient descent will find the weights, or how well the result generalizes from a finite training set. Depth is part of the practical answer: some functions that a deep network represents compactly need exponentially many units in a shallow one.

Extra: time, memory and performance

This section is optional extra material for readers who are interested in algorithms and performance engineering. It is not part of the course requirements: you do not need it for the exercises or the exam.

The core material describes what each method computes. This section asks what the computation costs: how time and memory grow with the size of the data and of the model, and why the same arithmetic can run ten or a hundred times faster depending on how it is arranged. We count multiply–accumulate operations (MACs; one MAC is two floating-point operations, or FLOPs) and bytes. Notation: N training examples, mini-batches of B examples, P parameters and E epochs.

Dense layers: about six FLOPs per parameter per example

A dense layer with n inputs and m outputs has mn + m parameters and needs mn MACs for one example. For a mini-batch, the inputs are the rows of a matrix X, and the whole batch is one matrix product:

Z = X W^\top + \mathbf{1}\, b^\top, \qquad X \in \mathbb{R}^{B \times n},\ W \in \mathbb{R}^{m \times n}: \qquad B\,m\,n \ \text{MACs}.

Summed over the layers, a forward pass costs about one MAC per weight per example, or 2P FLOPs. The backward pass costs about twice as much, because each layer computes two products of the same size: the gradient for its input, G W, and the gradient for its weights, G^\top X, where G holds the derivatives of the loss with respect to Z. One training step therefore costs about 6P FLOPs per example, and training costs

\text{FLOPs} \approx 6\,P\,N\,E.

The batch size does not appear: it changes the number of updates (N/B per epoch) and how efficiently the hardware works, not the amount of arithmetic. For the digit network of the core material, P = 31{,}810, so one training step costs about 6P \approx 191{,}000 FLOPs per image, and the 8 epochs over the 6,400 training images of the exercise need about 9.8 \cdot 10^{9} FLOPs. One modern CPU core with vector instructions can do on the order of 10^{11} FLOPs per second (for example 3 GHz × 2 fused multiply–add units × 8 single-precision lanes × 2 FLOPs), so the arithmetic alone would take about 0.1 seconds. Real code takes longer: small matrices, memory traffic and the Python interpreter add overhead. Closing that gap is the work of performance engineering.

Memory. Training keeps four kinds of numbers: the P parameters, their P gradients, the optimizer's state (none for plain SGD, P for momentum, 2P for Adam) and the activations of every layer, which the backward pass needs: B \sum_\ell n_\ell values for layer widths n_\ell, the input included. Prediction needs only the parameters and the activations of the current layer. For the digit network, the parameters take 127 KB as 32-bit floats, small enough to stay in a CPU core's cache, and the activations of a batch of 200 images take 0.67 MB.

Performance: choose the number format. The 70,000 MNIST images take 439 MB as 64-bit floats, which fetch_openml returns, 220 MB as 32-bit floats and 55 MB as bytes. This is why the exercise converts them with astype("float32"): half the memory traffic, and twice as many numbers in each vector instruction (8 instead of 4 in a 256-bit AVX2 register). Neural networks rarely need 64-bit precision, and GPUs go further: they train in 16-bit formats (see the checklist below).

Why mini-batches are fast: arithmetic intensity

A processor can compute only as fast as it receives data. The arithmetic intensity of a computation is the number of FLOPs it performs per byte that it moves to or from memory. A matrix–vector product, one example at a time, uses each weight once: 2 FLOPs per weight, about 1 FLOP per byte with 16-bit weights. A mini-batch of B examples reuses each weight B times, so the intensity grows with B. The roofline model turns this into a speed limit:

\text{attainable FLOP/s} = \min\bigl(\text{peak FLOP/s},\ \text{memory bandwidth} \times \text{arithmetic intensity}\bigr).

On the illustrative device of the figure, a layer of width 4096 reaches 1% of the peak at batch size 1, 16% at batch size 16 and the full peak at 128. Below the ridge point (here 100 FLOP per byte) a computation is memory-bound: faster arithmetic does not help, only less data movement does. Above it, the computation is compute-bound. Matrix libraries (BLAS on CPUs, cuBLAS on NVIDIA GPUs) get close to the peak by splitting the matrices into tiles that stay in registers and caches while they are reused. You can see the effect on a laptop: 

import time
import numpy as np

rng = np.random.default_rng(0)
W = rng.standard_normal((4096, 4096), dtype=np.float32)   # 64 MiB of weights
X = rng.standard_normal((256, 4096), dtype=np.float32)    # a mini-batch of 256 inputs

t = time.perf_counter()
for x in X:                  # 256 matrix-vector products: W is read 256 times
    W @ x
loop = time.perf_counter() - t

t = time.perf_counter()
X @ W.T                      # one matrix-matrix product: each weight is reused 256 times
gemm = time.perf_counter() - t
print(f"loop {loop:.3f} s, one product {gemm:.3f} s, {loop / gemm:.0f}x faster")

Both versions do the same 8.6 \cdot 10^{9} FLOPs. The loop streams the 64 MiB weight matrix from memory 256 times, 16 GiB in total; the single product reads it about once and reuses each tile from the cache. On the 4-core machine used to test this page, the single product was 7 to 10 times faster, and on a GPU the difference is larger. Mini-batches are useful for statistical reasons, as the core material explains, and they are also what makes neural networks fast on real hardware.

The perceptron: cheap steps, but in sequence

A perceptron prediction costs O(d) for d inputs, so one epoch costs O(Nd) time and O(d) memory besides the data. How many epochs are needed? The convergence theorem (Novikoff, 1962) answers with the geometry of the data. Use the labels −1 and +1 and a constant input 1 for the bias. If every input satisfies \lVert x \rVert \le R and some unit vector u separates the classes with margin \gamma, that is y\, u \cdot x \ge \gamma for every example, then the perceptron makes at most

\left( \frac{R}{\gamma} \right)^{2} \ \text{mistakes}.

Each epoch before convergence makes at least one mistake, so training takes at most (R/\gamma)^2 + 1 epochs and O\bigl(Nd\,(R/\gamma)^2\bigr) time. Classes that are separable but nearly touch have a small margin and can need many epochs. For XOR no margin exists, and the bound says nothing.

Performance: vectorize what is independent. Each perceptron update changes the weights that the next example sees, so the loop over the examples is inherently sequential: only the dot product inside each step can use vector instructions. A mini-batch gradient step is different: all B examples use the same weights, so their gradients come from one matrix product. When a sequential loop is unavoidable, run it as compiled code (C++, Numba or jax.lax.scan) instead of in the Python interpreter, where each iteration costs far more than its arithmetic.

Convolutions: many operations per parameter

A convolutional layer with C_\text{in} input channels and C_\text{out} filters of size k \times k computes H_\text{out} W_\text{out} C_\text{out} outputs, each with k^2 C_\text{in} MACs:

\text{time} = H_\text{out}\, W_\text{out}\, C_\text{out}\, k^2\, C_\text{in} \ \text{MACs per image}, \qquad \text{parameters} = (k^2 C_\text{in} + 1)\, C_\text{out}.

The core material's 16 RGB filters of size 3 × 3 have 448 parameters. On a 32 × 32 image with padding 1, they do 32 \cdot 32 \cdot 16 \cdot 27 = 442{,}368 MACs: about 1,000 per parameter, where a dense layer uses each weight once per example. This high arithmetic intensity is one reason why CNNs run well on GPUs. The cost moves to memory instead: one 224 × 224 feature map with 64 channels holds 3.2 million values, 12.8 MB as 32-bit floats, so a batch of 32 images needs 411 MB for this single layer, all of it kept for the backward pass.

Performance: one operation, several algorithms. Libraries implement a convolution in different ways. im2col copies each patch into a column of a matrix and calls a fast matrix product, at the price of about k^2 times more memory for the copied input (Chellapilla et al., 2006). Winograd's minimal filtering computes a 2 × 2 block of outputs of a 3 × 3 filter with 16 multiplications instead of 36, 2.25 times fewer (Lavin and Gray, 2016). FFT-based methods suit large filters. cuDNN on NVIDIA GPUs chooses among such algorithms for each layer shape; in PyTorch, torch.backends.cudnn.benchmark = True lets it time them once and keep the fastest. The memory layout matters too: "channels last" (NHWC) stores the channels of one pixel next to each other, which suits vector instructions and tensor cores.

Embeddings and recurrent networks

An embedding lookup copies one row of the table: O(d) per token, where multiplying a one-hot vector by the table would cost O(Vd) for the same result. The table can be the largest part of a model, as in recommender systems, and the backward pass changes only the rows of the tokens in the batch. Finding the nearest neighbours of one vector among V vectors costs O(Vd): normalize the table once, and all cosine similarities are one matrix–vector product. For millions of vectors, approximate nearest-neighbour indexes such as HNSW (Malkov and Yashunin, 2020) give up a little accuracy for much faster search; vector databases are built on them.

A recurrent step h_t = \tanh(W_x x_t + W_h h_{t-1} + b) costs d_h (d_x + d_h) MACs, so a sequence of length T costs O\bigl(T d_h (d_x + d_h)\bigr) time, and training stores all T hidden states: O(T d_h) memory per sequence. Performance: the steps cannot run in parallel, because step t needs h_{t-1}; only the sequences of a batch can. Attention in Week 5 removes this dependency and processes all positions at once, at the price of comparing every pair of positions: O(T^2) work in parallel instead of T sequential steps.

A performance checklist

  • Measure first. Profile before you optimize: cProfile or py-spy for Python, torch.profiler for PyTorch, Nsight Systems for NVIDIA GPUs. The slow part is often not where you expect it.
  • Find the limit. Compare the achieved FLOP/s with the peak, and the achieved bytes per second with the memory bandwidth. A memory-bound computation needs less data movement, not faster arithmetic.
  • Use smaller number formats. 32-bit instead of 64-bit floats on CPUs. On GPUs, mixed precision computes in 16-bit formats on tensor cores and accumulates in 32 bits (Micikevicius et al., 2018). bfloat16 has the exponent range of 32-bit floats; float16 needs loss scaling to keep small gradients from becoming zero.
  • Choose friendly shapes. Tensor cores work best when matrix dimensions are multiples of 8 for 16-bit numbers, and larger multiples often help further.
  • Keep the device busy. Load and preprocess the next batches in background workers while the current one trains. A GPU that waits for data shows low utilization.
  • Trade computation for memory. Gradient checkpointing stores the activations of only some layers and recomputes the others during the backward pass: about \sqrt{L} stored layers instead of L, for about one extra forward pass (Chen et al., 2016).
  • Fuse small operations. A chain of element-wise operations, each reading and writing a whole tensor, is memory-bound. Compilers such as torch.compile and XLA fuse them into one pass.
