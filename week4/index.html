    From perceptrons to multilayer networks

    Neural networks are models whose parameters are learned from examples. They are built by composing simple transformations. This makes it possible to learn useful intermediate representations instead of requiring every feature to be designed by hand.

    The perceptron

    A perceptron receives an input vector x, multiplies each input by a learned weight, adds a bias, and applies a threshold. In compact form, it predicts from w^\top x + b. During training, the weights are adjusted when the prediction is wrong. A perceptron can learn a linear decision boundary, but it cannot represent every classification problem.

    For example, with inputs (1, 2), weights (0.7, -0.2), and bias 0.1, the weighted sum is 0.7 \times 1 - 0.2 \times 2 + 0.1 = 0.4. A step activation produces class 1 because the result is positive. The weights determine the position and orientation of the separating line; the bias moves it without changing its orientation.

    The limit of a single boundary

    The perceptron learning rule converges when the classes are linearly separable. It cannot solve XOR: no single straight line can place the two blue points on one side and the two orange points on the other. This is a representational limitation, not a failure to train long enough.

    Multilayer perceptrons

    A multilayer perceptron combines neurons into an input layer, one or more hidden layers, and an output layer. Each layer transforms the representation produced by the previous layer. Width gives a layer more units with which to represent patterns, while depth allows the model to build more complex transformations from simpler ones.

    A forward pass applies these transformations from the input to the prediction. For a layer, the main calculation is a linear transformation followed by an activation function:

    h = \operatorname{activation}(Wx + b)

    Why activation functions matter

    Without nonlinear activation functions, stacking layers would still produce only a linear model. ReLU is widely used because it is simple and works well in many settings. Sigmoid maps values between zero and one, while tanh maps them between minus one and one. The activation function influences how easily the network trains and what kinds of decision boundaries it can learn.

    \sigma(z) = \frac{1}{1 + e^{-z}}, \qquad \tanh z = \frac{e^{z} - e^{-z}}{e^{z} + e^{-z}}, \qquad \operatorname{ReLU}(z) = \max(0, z)

    Learning representations

    Training a neural network

    Training begins with a loss function that measures the difference between predictions and target values. Backpropagation applies the chain rule to calculate how each parameter contributed to that loss. An optimizer then uses the resulting gradients to update the parameters. For this course, the important idea is the division of labour: the forward pass produces a prediction, the loss evaluates it, backpropagation supplies gradients, and the optimizer updates the model.

    Performance on the training data alone is not enough. We use separate validation and test data to evaluate whether a network generalizes to new examples. Excessive model capacity or training can lead to overfitting. Regularization, suitable model size, and early stopping can reduce this problem.

    Embeddings

    An embedding represents a discrete item, such as a word, as a vector of learned numbers. Items used in similar contexts tend to acquire similar vectors. Embeddings therefore replace arbitrary identifiers with representations in which distance and direction can encode useful relationships. The same idea is used for text tokens, images, users, products, and many other kinds of data.

    Summary

    Neural networks learn layered representations by combining linear transformations with nonlinear activation functions. Training adjusts their parameters using gradients. Embeddings extend representation learning to discrete items such as words and prepare the ground for attention and Transformers in Week 5.

    Training Your First Neural Network (programming) (1.5p)

    Time to stop drawing perceptrons on paper and actually train one. We'll use scikit-learn's MLPClassifier, which hides the training loop (forward pass, loss, backward pass, weight update) behind a single .fit() call — exactly the same building blocks you've read about, just already wired up for you.

    Run this on the MNIST digit data. The code loads MNIST via sklearn.datasets.fetch_openml("mnist_784"); you can also reuse mnist-x.data/mnist-y.data from Perceptron.zip (6,000 images whose pixels are already 0 or 1, so skip the division by 255), as long as you split them into training and test sets: 

    from sklearn.datasets import fetch_openml
from sklearn.neural_network import MLPClassifier

X, y = fetch_openml("mnist_784", version=1, return_X_y=True, as_frame=False)
X = X / 255.0                   # scale the pixel values from 0..255 to 0..1
X_train, X_test = X[:60000], X[60000:]
y_train, y_test = y[:60000], y[60000:]

clf = MLPClassifier(
    hidden_layer_sizes=(40,),   # one hidden layer, 40 neurons
    max_iter=8,
    solver="sgd",
    learning_rate_init=0.2,
    random_state=1,
)
clf.fit(X_train, y_train)
print("Test accuracy:", clf.score(X_test, y_test))
    1. Run the code above as-is and note the test accuracy.
    2. Change hidden_layer_sizes=(40,) to (10,), then to (100, 50) (two hidden layers). Rerun each and record the accuracy.
    3. Change max_iter=8 to 50 (keeping hidden_layer_sizes=(40,)) and rerun.
    4. In 3–4 sentences: which change helped most, which helped least or hurt, and does that match your intuition about network capacity vs. training time?
    What's actually happening inside .fit()?

    With solver="sgd", each of the 8 iterations (max_iter) is an epoch, one pass over the whole training set. The data is processed in mini-batches of 200 images (the default batch_size), and for each mini-batch the network does exactly what you've seen in lecture: a forward pass, a loss computation, a backward pass and a weight update via gradient descent. With 60,000 training images, that is 300 weight updates per epoch. What makes this more than the perceptron you studied earlier is the training rule: MLPClassifier minimizes a differentiable loss (cross-entropy) and uses backpropagation to work out how every weight, including those of the hidden layer, should change. The perceptron learning rule can only train a single layer of weights.

    Backpropagation by hand: XOR in NumPy

    MLPClassifier and Keras hide the training loop. Here it is in full, for the XOR problem that a single perceptron cannot solve: two inputs, a hidden layer of four \tanh units, a sigmoid output and the cross-entropy loss. The backward pass is the chain rule applied layer by layer, from the loss back to the first weights. 

    import numpy as np

X = np.array([[0, 0], [0, 1], [1, 0], [1, 1]], dtype=float)
y = np.array([[0], [1], [1], [0]], dtype=float)                 # XOR

def train(W1, b1, W2, b2, steps=5000, lr=0.5):
    for _ in range(steps):
        # Forward pass
        h = np.tanh(X @ W1 + b1)                                 # hidden layer, shape (4, 4)
        p = 1 / (1 + np.exp(-(h @ W2 + b2)))                     # output probability, shape (4, 1)
        # Backward pass: the chain rule, layer by layer
        d_out = (p - y) / len(X)                                 # dLoss/d(output logit)
        d_W2, d_b2 = h.T @ d_out, d_out.sum(axis=0)
        d_h = d_out @ W2.T * (1 - h ** 2)                        # tanh'(z) = 1 - tanh(z)^2
        d_W1, d_b1 = X.T @ d_h, d_h.sum(axis=0)
        # Gradient descent step
        W1 -= lr * d_W1; b1 -= lr * d_b1; W2 -= lr * d_W2; b2 -= lr * d_b2
    return p

rng = np.random.default_rng(1)
p = train(rng.normal(0, 1, (2, 4)), np.zeros(4), rng.normal(0, 1, (4, 1)), np.zeros(1))
print(p.ravel().round(3))                                         # [0.    0.999 0.999 0.002]

    The line d_out = (p - y) / len(X) is worth a second look: for a sigmoid output with the cross-entropy loss, the derivative of the loss with respect to the output's logit is simply p - y, the prediction minus the target. Everything else is matrix calculus that a framework like PyTorch does for you with automatic differentiation.

    Why the starting point matters

    Try two experiments with the code above. First, change the seed to 0: this time the network gets stuck on a plateau and predicts about 0.5 for two of the four inputs (in our runs, 19 of 20 seeds solved XOR). Gradient descent finds a low point, not necessarily the best one. Second, start every weight at 0.5 instead of a random number. Now all hidden units compute the same thing and receive the same gradient, so they stay identical forever: the network behaves as if it had one hidden unit, and it cannot solve XOR. Random initialization breaks this symmetry, and choosing its scale well (Xavier or He initialization) keeps the signals in deep networks from fading or exploding.

    What the universal approximation theorem says, and what it does not

    A network with one hidden layer can approximate any continuous function on a bounded region as closely as you like, given enough hidden units: Cybenko (1989) proved this for sigmoids, and Leshno, Lin, Pinkus and Schocken (1993) for every continuous activation that is not a polynomial. It is often quoted as "neural networks can learn anything". It does not say that: it says nothing about how many units are needed (possibly astronomically many), whether gradient descent will find the weights, or how well the result generalizes from a finite training set. Depth is part of the practical answer: some functions that a deep network represents compactly need exponentially many units in a shallow one.
