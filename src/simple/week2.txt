== 1bb6a347
In this section, we study methods for uncertainty. In the history of AI, people used different methods for uncertain and imprecise information. Some examples are fuzzy logic, non-monotonic logic and the theory of plausible reasoning <i> et cetera</i>. In most cases, probability theory is the best method for reasoning under uncertainty. It has the clearest principles and it is the most consistent.

== 0559cfc5
My opinion on this topic is not objective. A rigorous formal proof, Cox's theorem, shows this: each method of inference that uses real numbers for degrees of plausibility, and that satisfies some more requirements, is equivalent to probability theory. (One requirement is that the method agrees with ordinary two-valued logic.) A supporter of fuzzy logic tried to avoid this proof. His <a href="http://sipi.usc.edu/~kosko/Fuzziness_Vs_Probability.pdf">response</a> was: the proof uses <i>ordinary (two-valued) logic, thus it does not apply to fuzzy logic.</i> It is very difficult to argue against this! (But to be fair: fuzzy logic models vagueness, that is, degrees of truth. It does not model degrees of belief about statements that are true or false.)

== e13a23f2
The left side of the equation is the <strong>posterior probability</strong> (the probability after the observation). The first factor in the numerator is the <strong>prior probability</strong> (the probability before the observation). The second factor is the <strong>likelihood</strong> (how probable the observation is when the state is given). The denominator has many names. Possibly the best name is <strong>the annoying denominator</strong>. (The usual names are evidence and marginal likelihood.)

== 5cbf504e
In this example, the state is whether a person has a condition (a disease). The observation is a positive test. The prior is the percentage of people with the condition. The likelihoods are the probabilities of a positive test with the condition and without it. The posterior is the percentage of people with the condition among the people with a positive test. When a condition is rare, most positive tests can be false, also when the test is good.

== 095cdeac
The <strong>naive Bayes classifier</strong> is one of the most useful applications of the Bayes rule. It is a machine learning technique. It can <strong> classify</strong> objects (for example text documents) into two or more classes. To train the classifier, we analyse a set of <strong>training data</strong>. For the training data, we know the correct classes.

== 778cbce2
The naive Bayes model is a probabilistic model. It has one class variable (this is the state variable from above) and a number of feature variables. The model assumes that the feature variables are <strong> conditionally independent</strong> when the class is given. (This course does not discuss the exact meaning of conditional independence. You can find more about it in the literature. For this course, it is sufficient that you can use conditional independence when you build the classifier.)

== fd1c190c

In each case, we make a simple assumption: all words in the message have the same distribution. Also, as we said above, we assume that the words are independent of each other when the class (spam or ham) is given.

== dd4dca80

The simplest method: count how many times each word (<code>aardvark, aardwolf, ..., Zyzzogeton</code>) occurs in the corpus. Then divide this number by the total number of words in the corpus.

== 5847cc37
There is a problem when we estimate the probabilities directly from the counts: a count of zero gives a probability estimate of zero. This can make the classifier much worse. For example, the ratio of the posterior probabilities can easily become 0/0. Such a result is a "singularity" (a point where the calculation breaks), so we need a better method. The simplest solution is a small lower bound for all probability estimates. For example, the value 0.000001 is sufficient.

== 6d396cad

When the ratio of the two probabilities is the other way around, the word makes it more probable that the message is ham.

== c56ff690
With more than two classes (for example the ten digits of the naive Bayes classifier in Week 3), the same idea is the <b>log-sum-exp trick</b>: subtract the largest log score before you apply the exponential function. The scores <span class="math">-1000, -1002, -1010</span> all underflow to 0 with <code>math.exp</code>. Thus, if you normalise them directly, you divide 0 by 0. When you subtract the maximum first, you get the probabilities 0.881, 0.119 and 0.00004. The softmax in the attention layers of Week 5 is calculated in exactly this way.

== a2087ac3
The words are clearly not independent when the class is given: for example, "click" and "here" usually occur together. But naive Bayes classifies well. Domingos and Pazzani (1997) showed the reason. A classifier only needs the <i>largest</i> posterior to be correct. Naive Bayes is optimal under zero-one loss in many more situations than the situations where its independence assumption is true. But the probabilities are not good. The model counts correlated words as independent evidence, so the posteriors move very near to 0 and 1. The underflow figure above shows <span class="math">P(\text{spam} \mid \text{message}) = 1 - 1.97 \times 10^{-14}</span> after only 60 words. No honest model of email can be so sure. Use the ranking, not the number. Or calibrate the probabilities on held-out data (data that you did not use for training).
