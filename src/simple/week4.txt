== 338ba898
A neural network is a function with parameters. We make it from a sequence of simpler functions. Training changes the parameters, so that the outputs become useful for a task. This week has three important questions: <b>What can a network represent? How can it learn its parameters? How do we know that it learned something useful, also for examples that it did not see in training?</b> We use one example through the week: the recognition of handwritten digits. Small numerical examples show the calculations.

== 80e18c69
The word <i>neuron</i> is a mathematical analogy (a comparison). It does not mean that these models copy a biological brain. The architecture, the training objective and the data of a network set what it can learn. A large number of parameters alone does not explain intelligence, understanding or reliable behaviour.

== 25d1f6bf
Neural networks did not start with the large language models of today. They started when researchers tried to connect mathematical models of computation, learning and nervous systems. The history includes logical threshold units, classifiers that can learn, associative memories, self-organizing maps and deep representation learning. These research traditions overlap. They are not a simple sequence where each new model replaces all the models before it.

== 628ab1ae
<b>Be careful with the history:</b> it is not correct to say that one “AI winter” started in 1960. It is also not correct to say that one book caused a full decrease in research. AI funding and the interest in neural networks changed at different times, for different reasons. Also, no single person or paper made all parts of backpropagation. Reverse-mode differentiation, its use for learning and its popularity each have a different history.

== 84cf6cbe
A Turing machine shows computation as a sequence of steps that follow rules. Natural nervous systems do computation in a different way: many neurons are active <b>in parallel</b> (at the same time), their signals can be <b>stochastic</b> (random), and their connections can <b>adapt</b> (change) with experience. This is a difference in how the computation is organized. Usual computers can simulate neural networks. Also, parallel computation that adapts does not show that neural networks can calculate functions that a Turing machine cannot calculate. Most networks in this course are numerical programs on usual digital hardware.

== fcf4a95e
In <a href="../week1/#gofai-modern-ai">Week 1</a>, we compared symbolic AI (GOFAI) with approaches that learn from data. Symbolic AI frequently uses explicit symbols and rules. Neural networks usually learn <b>subsymbolic</b> representations: numerical patterns that are spread across many units. A unit does not have to show a concept that has a name. The two approaches can be used together, and both operate on digital computers. Thus, <i>digital</i> is not the difference between them.

== 89402a2f
Some neural networks model probabilities. Other networks, such as the perceptron below, always give the same prediction for the same inputs and weights (they are deterministic). People sometimes call neural networks <b>black boxes</b>. We can examine each weight and each activation, but it can be difficult to explain why a large network made a specific prediction. Also, a design that comes from the brain is not automatically evidence of consciousness or human-like understanding.

== 2083e5d2
The useful part of the analogy is this: many connected units can make complex behaviour, and a change of their connections can change this behaviour. A biological neuron is a living cell with dendrites, a cell body and an axon. Signals come in through synapses and change the activity of the cell. Many neurons send action potentials (electrical pulses) along the axon. At the synapses, they communicate with chemicals. The artificial unit keeps only a small part of this: inputs, connection weights that can change, a sum and an output function.

== 08efb036
Brains have many recurrent connections (connections that go back), many types of cells and interactions on many time scales. Artificial networks can be feedforward, recurrent, probabilistic or spiking. Thus, these two statements are not always true: “natural networks are binary, but artificial networks are continuous” and “artificial networks have no feedback”. A spike is an event. But the firing rate, the time of the spikes and other biological variables also carry information.

<b>Biology reference:</b> the US National Institute of Neurological Disorders and Stroke, <a href="https://www.ninds.nih.gov/publications/know-your-brain-brain-basics" target="_blank" rel="noopener">Know Your Brain</a>. == 6ce88ffa
A Hopfield network is an example of recurrent dynamics. Its state changes over time, and it can find a stored pattern from a cue (a start pattern) that is partial or damaged. Under suitable conditions, an energy function helps to analyze convergence. But this does not mean that each cue finds the correct memory. A Boltzmann machine uses random (stochastic) units in a probabilistic model that is based on an energy. A self-organizing map uses a different idea. The prototype that wins, and the prototypes near it, move toward an input. Thus, the map puts similar inputs near each other on a grid. These examples show that neural computation is more than supervised feedforward classification. They give context. You do not have to implement them this week.

== f285d1e1
The <b>MNIST</b> dataset, which you saw in <a href="../week3/#example-handwritten-digit-recognition-mnist">Week 3</a>, has images of handwritten digits with the labels 0 to 9. Each image has <span class="math">28 \times 28</span> grayscale pixels. The standard dataset has 60,000 training images and 10,000 test images. Some exercises use smaller subsets. A fully connected network can get an image as a vector of 784 numbers. A pixel value is a measurement. It is not an instruction such as “this is the upper loop of an eight.” The model must learn which combinations of measurements are useful. A training example is a pair: an input <span class="math">x</span> and a target <span class="math">y</span>, for example the digit label 8.

== 81706125
<b>The same data for two tasks.</b> For a single perceptron, select one digit and ask “Is this a 3?”. The digit 3 is then the positive class, and all other digits are the negative class. The full task asks “Which digit is this?”, and it has ten classes. A multilayer classifier can give ten scores, one for each digit. A <a href="#cnn">convolutional network</a> can keep the two-dimensional grid as its input. Thus, pixels that are neighbours in the image stay neighbours.

== e9533221
A training dataset has many of these pairs. When the model makes a prediction, it gets a new image without the correct label. Thus, its parameters must contain a rule that works for different handwriting, line thickness and position. A table of the images that it saw before is not sufficient. Features such as the pixel scale and the image resolution must be the same in training and in later use.

== 26e965f7
<b>Preprocessing:</b> MNIST pixels usually have values from 0 to 255. Divide by 255 to change them to the interval <span class="math">[0, 1]</span>. For other numeric features, standardization (a change of each feature to mean 0 and standard deviation 1) can help the optimization. If the preprocessing uses values from the data, calculate these values only from the training split. The input representation and the preprocessing are parts of the model pipeline.

== af3725cd
Here we use the labels 0 and 1, so the error term is −1, 0 or +1. The same formula also works with the labels −1 and +1. But then an incorrect prediction gives −2 or +2. Thus, the step size depends on the label convention and on <span class="math">\lambda</span>. Many texts use the update <span class="math">w' = w + \alpha\, y\, x</span> after a mistake, with signed labels. This update is the same when <span class="math">\alpha = 2\lambda</span>.

== 32f12d87

== 34e339bf
This rule corrects the errors of a perceptron. It is not a training formula for all neural networks. A sigmoid output with binary cross-entropy has a similar gradient update for one example: the error times the input, where <span class="math">\hat{y}</span> is a probability. == bddbe2a4
The perceptron learning rule converges: after a finite number of errors, it finds a line that separates the classes. This is true when a finite dataset is linearly separable and the usual assumptions of the convergence theorem are true. When the classes overlap, or when they need a nonlinear boundary, maybe no separating weights exist. More training cannot correct a limit of the model family.

== f34745f0
<b>Why no line works:</b> a line divides the plane into two half-planes. A half-plane is convex: if it contains two points, it also contains the midpoint between them. Put the two class-1 points on one side of a line. Then their midpoint <span class="math">(\tfrac12, \tfrac12)</span> must also be on that side. Put the two class-0 points on the other side. Then the same midpoint must be on that other side. A point cannot be on the two sides at the same time. Thus, no single line works in the original input space, also if we train for a very long time.

== fb890b7a
The perceptron predicts +1 when <span class="math">w \cdot x + b \ge 0</span>. If not, it predicts −1. It goes through the examples in a fixed sequence. After each mistake, it applies the learning rule above with <span class="math">\lambda = 0.5</span>. With the labels −1 and +1, a mistake gives <span class="math">y - \hat{y} = \pm 2</span>. Thus, the update adds <span class="math">y\,x</span> to <span class="math">w</span> and <span class="math">y</span> to <span class="math">b</span>. On linearly separable data, the mistakes stop after a finite number of updates. On XOR, the mistakes never stop.

== 8da9093f
A single perceptron gets the two inputs at the same time. If the two weights are 1, its score before the bias is <span class="math">s = x_1 + x_2</span>. The sum is 0 when the two inputs are off, 1 when they are different and 2 when the two inputs are on. Thus, the score already contains the necessary information. The problem is that one threshold cannot accept only the middle value. If it accepts the scores above 0.5, it accepts 1 and 2. If it accepts the scores below 1.5, it accepts 0 and 1. Other weights do not solve this problem for a single perceptron, as the diagonals that cross show.

== 8db33857
Two hidden units can test the two thresholds separately. One unit is on when <span class="math">s \ge 0.5</span>, and the other unit is on when <span class="math">s \ge 1.5</span>. The output accepts an input only when the first unit is on and the second unit is off. On the original input plane, this selects the strip between the two parallel lines in the plot on the right. The hidden units get the same inputs as the single perceptron. The difference is this: their nonlinear activations let the network combine two separate tests.

== 2b7db9a7
One unit asks <b>“Is one input or more on?”</b> The other unit asks <b>“Are the two inputs on?”</b> For XOR, the answer to the first question is yes, and the answer to the second question is no. In the table, the two class-1 cases now go to the same hidden point, <span class="math">(1, 0)</span>. The output unit can separate this point from <span class="math">(0, 0)</span> and <span class="math">(1, 1)</span> with a straight line in the <em>hidden-feature space</em> (the space of the hidden features).

== 15dac350

Set <span class="math">h_1 = \operatorname{step}(x_1 + x_2 - 0.5)</span> and <span class="math">h_2 = \operatorname{step}(x_1 + x_2 - 1.5)</span>. The output is <span class="math">\operatorname{step}(h_1 - 2h_2 - 0.5)</span>. Try the input <span class="math">(1, 1)</span>. The two units are on. Thus, the output score is <span class="math">1 - 2 - 0.5 = -1.5</span>, and the output is 0.

== 1719c0a3
This is the step from XOR to multilayer networks. A hidden layer changes the input, and the output layer classifies this new representation. The nonlinear step functions make this possible. Without a nonlinearity, layers on top of each other become one weighted sum plus a bias, as the section about <a href="#activations">nonlinear activations</a> shows. We selected the XOR features by hand. In a multilayer network that we train, the goal is to <em>learn</em> useful hidden features from examples.

== ce441fc5
<b>Know the dimensions:</b> a digit classifier has 784 inputs, 40 hidden units and 10 outputs. Its first weight matrix has the shape <span class="math">40 \times 784</span>, and its first bias vector has the length 40. The second matrix has the shape <span class="math">10 \times 40</span>, and the output bias vector has the length 10. Thus, the network has <span class="math">784 \times 40 + 40 + 40 \times 10 + 10 = 31{,}810</span> parameters that training can change. The input layer only holds the data. It does not add trainable weights.

A deep network can represent some functions much more compactly. But the data, the stability of the training and the architecture are also important. A hidden unit does not always show a concept that a person can easily name.

== 78a25808
Backpropagation multiplies by the derivative of the activation function. The derivative of the step function is zero at all points except 0, where it has no value. Thus, it gives no gradient for learning. The derivative of the sigmoid is <span class="math">\sigma'(z) = \sigma(z)\bigl(1 - \sigma(z)\bigr)</span>. Its maximum value is 0.25. The derivative of tanh is <span class="math">1 - \tanh^2 z</span>. Its maximum value is 1. The derivative of ReLU is 0 for negative inputs and 1 for positive inputs.

== e90e1863
The hidden activations and the output function can be different. A regression model can use a numeric output with no limits. Binary classification frequently uses a sigmoid. Digits have ten classes, and only one class can be correct. For them, <b>softmax</b> changes ten scores (logits) into values that are not negative and that have the sum 1. A large softmax value can be wrong, or it can be poorly calibrated. It does not make sure that the prediction is correct.

== 2d88fb18
<b>A loss answers a new question:</b> for the prediction and the known target, how bad was this prediction? If a small network predicts 2 and the target is 1, the residual (the difference) is 1, and the half-squared loss is 0.5. The loss is one number. It is not a list of weight corrections. We must still find how a change of each weight changes the loss. This is the work of <a href="#backprop">backpropagation</a>. There, we use the squared loss because the arithmetic is easy. Digit classifiers usually use cross-entropy with class scores.

== a3f82447
A <b>loss function</b> measures the difference between the output and the target. For a regression example with one number as the prediction <span class="math">\hat{y}</span>, we can use <span class="math">L = (\hat{y} - y)^2 / 2</span>. For binary classification, cross-entropy gives a large loss when the probability <span class="math">p</span> of the correct label is low:

== 4381fc01
If the correct class gets the probability 0.8, the multiclass loss is approximately 0.223. At the probability 0.2, it is approximately 1.609. Thus, the loss shows a difference between two predictions, also when they select the same top class. Accuracy counts the correct classifications. The loss gives a learning signal with many levels. In libraries, cross-entropy frequently accepts logits. It then does the output transformation and the logarithm in one operation that is numerically stable.

== 2dc3c8a8
The objective is usually the average loss over the examples, sometimes with a regularization term. The objective is a design decision. Bad labels or a bad objective can give a model that optimizes the training task, but does not help with the real-world purpose.

== 163133c1

A positive derivative means this: a small increase of the parameter increases the loss. Thus, gradient descent moves the parameter in the opposite direction, with the learning rate <span class="math">\eta</span>:

== 949fc837
This is a local calculation. It does not make sure that you get the best possible network.

== 6d268115
<b>Backpropagation</b> calculates the gradients efficiently. It applies the chain rule through the computation graph. It uses the intermediate results from the forward pass again, and it sends the sensitivities backward. Then the <b>optimizer</b> uses the gradients to change the parameters. Backpropagation and gradient descent are different operations, but both occur during training.

== 7e26c1b5
Think again about XOR. We designed its hidden units by hand, so we already knew which features solve the problem. In a real digit classifier, the labels tell which digit is in the image. But they do not tell what each hidden unit must find. The training problem is to find how each hidden weight changes the final prediction, and thus the loss.

== 418e8ac7
Think about a weight that sends its value to a hidden unit. A change of the weight first changes the input score of the unit. This can change its activation, which can change the prediction, which can change the loss. The chain rule multiplies the sensitivities (the rates of change) along this route. If more than one route connects the weight to the loss, we add their contributions. When we work backward, we calculate a sensitivity near the loss only one time. Then we use it again for all the weights before it that depend on it.

== 8f88c1bf

ReLU has the slope 1 on its positive side. In the example below, the hidden unit is on that side, so the gradient goes through it.

== 17b5b7dc

With the learning rate 0.1, change all four parameters with these gradients: <span class="math">w = 0.1</span>, <span class="math">b = -0.2</span>, <span class="math">v = 1.9</span> and <span class="math">c = -0.1</span>. == 0f8b2770
<b>More explanation:</b> <a href="https://d2l.ai/chapter_multilayer-perceptrons/backprop.html" target="_blank" rel="noopener">Dive into Deep Learning: forward propagation and backpropagation</a>. Start with its computational graph, and follow one variable backward. Larger networks apply the same chain rule with matrix operations and automatic differentiation.

== be206de8
<b>One cycle of the loop:</b> take a mini-batch of 100 MNIST images. The forward pass gives ten scores for each image. The labels change these scores into 100 losses, and we calculate their average. Backpropagation calculates the gradient of this average at the <em>current</em> weights. It calculates the full gradient before a weight changes. Then the optimizer does one step. The network predicts the next batch with the new weights. This was one update, not one epoch (see <a href="#optimization">epochs, batches and optimizers</a>). The last three lines of the pseudocode use the validation data and the test data, but they do not change the weights. The section about <a href="#generalization">generalization</a> tells why we keep these data separate.

== 6a3b2413
<b>Reading:</b> <a href="https://docs.pytorch.org/tutorials/beginner/basics/optimization_tutorial.html" target="_blank" rel="noopener">PyTorch: Optimizing Model Parameters</a>. Compare its training loop, which changes the weights, with its test loop, which does not change them. PyTorch adds each new gradient to the gradient that it keeps. Thus, at each step, the training loop sets the gradients to zero again with <code>optimizer.zero_grad()</code>. Do not remove this step, unless you want to add the gradients of many batches together.

== 507205c1
The first line of the pseudocode looks like a small detail. But gradient descent can only improve the weights that it starts from. The figure above starts from random weights, and its <i>New initial weights</i> button gives a different set. Two simpler start values do not work, for two different reasons.

== b8de09b5
<b>All zeros: the hidden layer never learns.</b> Start the small network of the <a href="#backprop-example">numerical backward pass</a> with <span class="math">w = b = v = c = 0</span>. The forward pass gives <span class="math">z = 0</span>, <span class="math">h = \operatorname{ReLU}(0) = 0</span> and <span class="math">\hat{y} = 0</span>. In the gradient table, <span class="math">\partial L / \partial c = -1</span>. But <span class="math">\partial L / \partial v = (\hat{y} - y)\, h = 0</span>, because <span class="math">h = 0</span>. Also, <span class="math">\partial L / \partial w = \partial L / \partial b = 0</span>, because the error gets to the hidden unit through <span class="math">v = 0</span>. Only <span class="math">c</span> changes. After the step, <span class="math">h</span> and <span class="math">v</span> are still 0, so the same thing occurs again. The network stays a constant, <span class="math">\hat{y} = c</span>, for all inputs and for all of the training. With tanh units, the result is the same, because <span class="math">\tanh 0 = 0</span>.

== b66574a4
<b>Equal weights: the units stay copies.</b> Zero is the extreme case of a larger problem. Sometimes all units of a hidden layer start with the same incoming weights and the same outgoing weights. Then they calculate the same activation for each input. Thus, backpropagation gives the same gradient to each unit, and the optimizer moves each unit by the same quantity. After any number of steps, the units are still the same. A layer of 100 such units cannot represent more than one unit. Random start weights break this <b>symmetry</b>. Each unit starts at a different point, gets a different gradient and can learn a different feature. The biases can start at 0, because the random weights already make the units different.

== 16c1c84e
In the start with all zeros above, use the sigmoid in place of ReLU. Now <span class="math">h = \sigma(0) = 0.5</span>. Thus, <span class="math">\partial L / \partial v = (\hat{y} - y) \times 0.5</span> is not zero, and <span class="math">v</span> moves at the first step. From the second step, the error also gets to <span class="math">w</span> and <span class="math">b</span>. The weights change. But if there are many hidden units, each unit changes in exactly the same way, so the units stay copies. Here, the symmetry stops the network, not a zero gradient.

== 70bd9f8f
<b>The scale is also important.</b> A unit adds <span class="math">n_{\text{in}}</span> terms <span class="math">w_i h_i</span>. The weights can be independent of each other and of the inputs, with the mean 0 and the variance <span class="math">\sigma^2</span>. Then the pre-activation of the unit has this variance:

== 3c95a26c
Some units are almost linear near 0, for example tanh units. For these units, each layer multiplies the variance of the signal by approximately <span class="math">n_{\text{in}} \sigma^2</span>. The backward pass multiplies the gradients by the same weights (transposed). Through many layers, a factor a little above 1 makes the activations and the gradients very large (they explode). A factor a little below 1 makes them very small (they vanish). Weights that are too large also push tanh and sigmoid units into their flat regions, where the derivative is almost 0. <b>Xavier/Glorot initialization</b> (Glorot and Bengio, 2010) uses <span class="math">\sigma^2 = 2 / (n_{\text{in}} + n_{\text{out}})</span>. This value is a compromise. It keeps the forward signal (<span class="math">1 / n_{\text{in}}</span>) and the backward gradients (<span class="math">1 / n_{\text{out}}</span>) at an almost constant scale. <b>He initialization</b> (He et al., 2015) uses <span class="math">\sigma^2 = 2 / n_{\text{in}}</span> for ReLU. ReLU sets approximately half of the pre-activations to 0. Thus, it decreases <span class="math">\mathbb{E}[h^2]</span> by half. For the first layer of the digit network, with 784 inputs and 40 units, the two methods give a standard deviation of approximately 0.05.

== 78e6ee3e
Usually, you do not set these scales yourself, because the libraries apply them automatically. For example, the dense layers of Keras and the <code>MLPClassifier</code> of scikit-learn use start weights at the scale of Glorot. You use these two libraries in the exercises of this week. Deep modern architectures have two more protections: normalization layers and residual connections. They also help to keep the signals and the gradients at a usable scale during training. A random seed lets you get the same run again. But some hardware and software operations can still give small differences.

== 67ba4121
This is the network of the numerical backward pass, but with three hidden units: <span class="math">\hat{y} = \sum_{j=1}^{3} v_j \operatorname{ReLU}(w_j x + b_j) + c</span>. Gradient descent (learning rate 0.1) trains it on five points of <span class="math">y = |x|</span>. The table shows each parameter, and its gradient ∇ under it. The chart shows the parameters during training. One unit can bend the line only one time. Thus, the V shape needs two or more units that are different. If all values start at zero, all gradients are exactly 0, but not the gradient of the output bias <span class="math">c</span>. Thus, only <span class="math">c</span> learns, and the network stays a horizontal line that goes up to the mean of the targets. If all values start at 0.5, the three units stay copies, and the line bends only one time. If the weights start as random values at the scale of He, the units become different, and they fit the V. Some random starts also fail. For example, a unit can be 0 at all training points. Then ReLU gives it no gradient.

== 628a9fca
<b>Neural Networks I checkpoint:</b> explain the function of each arrow in the training diagram. Which operation uses labels? Which operation calculates derivatives? Which operation changes the weights? At usual inference time (when the model makes predictions), a trained classifier does a forward pass. == fe35d0d2
An <b>epoch</b> is one pass through the training examples. A <b>mini-batch</b> is a group of examples. We use it to estimate the gradient for one parameter update. With 6,000 training examples and the batch size 100, one epoch usually has 60 updates. Eight epochs have approximately 480 updates, not eight. The training loss is frequently noisy, because different batches have different examples. For example, a batch with many sevens can need a different update than a batch with many threes. Thus, the loss can increase for some batches, while the general trend improves.

== 06d60480
Full-batch gradient descent uses the full training set for one update. Stochastic gradient descent with single examples makes an update after each example. Mini-batches are a practical compromise: the computation is efficient, and the gradient is a noisy approximation of the full gradient. The batch size controls how many examples give the direction of a step. The learning rate controls the length of the step. A larger batch changes how the optimization behaves and how many resources it uses. It does not automatically give better generalization.

== c0b5f096
<b>Learning rate:</b> if it is too small, the progress can be too slow for practical use. If it is too large, the steps can go past the minimum or diverge, as the worked example showed. A schedule changes the learning rate over time. Momentum collects information from the previous gradients. Adam keeps moving averages of the gradients and of their squares, and it adapts the updates with them. With all optimizers, you must still examine the data, the loss and the validation results.

== 4c02dd1a

The <b>validation set</b> helps you to make decisions, for example about the model size, the learning rate and when to stop training. == 8fb2fca4
A fully connected layer uses a separate input connection for each pixel position. But a small pattern, for example the corner of a stroke, can occur in many positions. A <b>convolutional layer</b> uses the same learned filter at different locations in the image. Local connections and shared weights contain a useful assumption: the same local pattern can be important at all positions.

== 990cf9b1
A filter multiplies a small patch of the image element by element. Then it adds the results, and usually also a bias. For the patch and the filter below, with zero bias, the result is <span class="math">1 - 4 = -3</span>:

== 35623948
When the filter moves over a larger image, it makes a feature map. Technically, this usual deep-learning operation is cross-correlation. But software usually calls the layer a convolution.

== 66e8a0bd
<b>Shared weights follow the pattern.</b> Think about a filter that responds to a short diagonal stroke. If the stroke moves to the right, the same filter still responds, but its response moves to the right on the feature map. Thus, the network does not need a separate detector for each pixel location. With the stride 1 and away from the borders, convolution is <b>equivariant</b> to translation: if the input moves, the feature map moves by the same distance. Thus, one convolution does not make a prediction <em>invariant</em> to shifts (the same for all shifts). It keeps the information about where the stroke was.

== 234bd0b4
<b>Compare the parameters:</b> an RGB filter with the height 3 and the width 3 has <span class="math">3 \times 3 \times 3 + 1 = 28</span> parameters, with its bias. Sixteen of these filters have 448 parameters. This number does not change with the number of locations where you apply them. But the feature maps can still be large. Thus, fewer parameters does not mean very little computation or memory.

== 8bc79cc5
The <b>stride</b> controls the distance that the filter moves between two locations. <b>Padding</b> adds a border, to control the output size. Pooling makes a summary of each local area and decreases the spatial resolution. Convolutions with a stride larger than 1 can also decrease the resolution. These operations can make the network more tolerant of small shifts. But a CNN is not automatically invariant to all translations, rotations or changes of the viewpoint.

== 1870c0ff
A typical CNN for digits learns some feature maps, combines them in later layers and gives class scores. Early filters can react to simple strokes. Later patterns can combine evidence from larger areas. This is an architectural bias (an assumption in the design). It does not make sure that each hidden unit has a clear meaning for people. <b>Connection to Week 5:</b> Vision Transformers use image patches and attention, not exactly this design with local filters. When you understand CNNs, you can understand this difference.

<b>Reading:</b> <a href="https://d2l.ai/chapter_convolutional-neural-networks/conv-layer.html" target="_blank" rel="noopener">Dive into Deep Learning: convolutions for images</a> and <a href="https://d2l.ai/chapter_convolutional-neural-networks/padding-and-strides.html" target="_blank" rel="noopener">padding and stride</a>; Goodfellow, Bengio and Courville, <a href="https://www.deeplearningbook.org/contents/convnets.html" target="_blank" rel="noopener">Chapter 9, §9.2</a>, about sparse connections, shared parameters and equivariance.

== 0234d297
The identifier (ID) of a word or token is arbitrary. If “cat” has the ID 12 and “dog” has the ID 13, their meanings are not similar because the numbers are near. A one-hot encoding does not have this incorrect sequence. But it uses one coordinate for each item in the vocabulary. An <b>embedding table</b> gives each item a learned vector with a dimension that you select. When you look up a token, you select one row of this table.

== 134611e4
A vocabulary of 10,000 tokens with 50-dimensional embeddings has 500,000 embedding parameters. The training task gives the signal that moves these vectors. A model starts with random vectors. It uses the row of a token to make a prediction, and the prediction error moves this row. In a task that predicts the context of words, words that occur in similar contexts can get similar vectors. Thus, context prediction, classification and recommendation can learn different types of similarity. The vectors do not get their meaning from the names of their coordinates. If you rotate the full space, the geometry between the pairs of vectors stays the same.

== c9cc68c7
For example, <span class="math">u = (1, 0)</span> and <span class="math">v = (1, 1)</span> have the cosine similarity <span class="math">1/\sqrt{2} \approx 0.707</span>. A value near 1 shows similar directions. It does not always mean that you can use one word in place of the other. Antonyms (words with opposite meanings) can occur in the same contexts, and their vectors can be near. Similarity is a learned association. It is not a universal measure of meaning.

== ab1496a8
Static embeddings give “bank” one vector, also when it means a river bank or a financial institution. Contextual networks calculate a different representation for each occurrence. The drawing above shows an example of a projection. It is not measured evidence that categories of meaning make tidy two-dimensional clusters. Embeddings can also show the biases or the gaps in their training data.

== 56538d64
“The dog chased the child” and “The child chased the dog” have the same words, but they describe different events. If you calculate the average of static word embeddings, you lose this sequence. A recurrent neural network (RNN) processes a sequence. It updates a hidden state again and again:

== 36203b69
It uses the same parameters at all positions. The hidden state depends on the inputs before the current position. For example, the state after “the dog chased” can be different from the state after “the child chased”, but the last word is the same. To use information from much earlier, the model must keep it through many updates, one after the other.

== cb66af13
The state is a learned summary. It is not a perfect memory. Through long sequences, the gradients can become very small or very large. Thus, it is difficult to learn dependencies over long distances. Gated architectures such as LSTMs and GRUs solve parts of this problem, but not all limits. This is an introduction to the concepts. You do not have to implement the gates this week.

== 0bfae681
<b>Bridge to attention:</b> an RNN must send each important detail through one recurrent state. Attention does not do this. It lets a representation combine information from selected positions. In <a href="../week5/">Week 5</a>, query–key scores set these combinations. Transformers also need information about positions, because a set of token vectors alone does not show the sequence. CNNs, RNNs and attention use different assumptions about how to combine information. They are not only larger and larger versions of the same model.

== 0a0853a7
Representation learning does not have to predict a class. Give the same handwritten eight to a classifier and to an autoencoder. The classifier tries to predict the label 8. The autoencoder tries to make the strokes of the image again. An <b>autoencoder</b> changes an input into a code with an encoder, <span class="math">z = \operatorname{encoder}(x)</span>. Then it makes the input again (it reconstructs it) with a decoder, <span class="math">\hat{x} = \operatorname{decoder}(z)</span>. The training target comes from the input. It is not a digit category that a person gives. A reconstruction loss measures the difference between the original data and the reconstructed data.

== ef2e352d
A bottleneck (a small code), a denoising objective or another constraint can prevent simple copying. For example, a 16-dimensional code must make a summary of a 784-dimensional image in a small space. This code can keep the style of the strokes and the identity of the digit, because both help the reconstruction. It is not always the best representation for classification. A network that is very flexible and has no constraints can learn the identity mapping (it only copies the input), which is not useful.

== 32eaf6ad
A standard autoencoder <b>does not automatically make realistic new images</b>. Random points in its code space can give bad images after the decoder. Models such as variational autoencoders add more structure, so that sampling works. Here we introduce the ideas of encoder–decoder and latent code, before the generative models of Week 5. == f2605fdc
<code>MLPClassifier</code> and Keras do the training loop for you, so you do not see it. The <a href="#backprop-example">numerical backward pass</a> above applied the chain rule by hand to one hidden unit. Here is the same calculation in matrix form, for the <a href="#xor">XOR problem</a>, which a single perceptron cannot solve. The network has two inputs, a hidden layer with four <span class="math">\tanh</span> units, a sigmoid output and the cross-entropy loss. The notation is the same as in the core material. Each row of <code>X</code> is one example, and a weight matrix has one row for each unit of its layer. Thus, <code>W1</code> has the shape 4 × 2, as the 40 × 784 matrix of the digit network. A layer calculates <span class="math">Z = X W^\top + b</span>.

== b255f91d
Look carefully at the line <code>G2 = (P - Y) / len(X)</code>. When the output is a sigmoid and the loss is cross-entropy, the derivative of the loss with respect to the logit of the output is only <span class="math">p - y</span>: the prediction minus the target. This is the error-times-input form from the <a href="#perceptron-update">perceptron rule</a>. Each layer then needs the two products from the <a href="#cost-dense">extra section below</a>. <code>G2 @ W2</code> sends the error back to the hidden layer, and <code>G1.T @ X</code> gives the weight gradient. A framework such as PyTorch calculates the same products for you with automatic differentiation.

== 651003b4
The <a href="#xor-hidden-layer">XOR section</a> set two hidden units by hand: "at least one input is 1" and "both inputs are 1". Gradient descent found a different representation. With seed 1, the printed matrix <code>H</code> shows it. The second hidden unit is near +1 only for the input (1, 0), and the fourth only for (0, 1). For the other inputs, both units are negative. The output weights, <code>params[2]</code>, are largest for these two units (about 7 each). Thus, the network calculates XOR as "<span class="math">x_1</span> and not <span class="math">x_2</span>, or <span class="math">x_2</span> and not <span class="math">x_1</span>". The other two units are large and positive for each input that contains a 1, and they are less important. Many hidden representations solve the same task. Training finds one of them, and it is not always the one that a person would design.

== 81112d46
Do two experiments with the code above. First, use only two hidden units, the size of the solution that we set by hand. In the last lines, change <code>(4, 2)</code>, <code>np.zeros(4)</code> and <code>(1, 4)</code> to <code>(2, 2)</code>, <code>np.zeros(2)</code> and <code>(1, 2)</code>. Two units can represent XOR. But in our runs, gradient descent solved it from only 52 of 100 random start values. Almost all other runs stopped with a prediction of about 0.5 for two of the four inputs (seed 0 is one of them). With three units, 84 of 100 runs solved XOR; with four, 98; with eight, all 100. The extra units are not necessary to represent the function, but they make it much easier to find. Second, give each weight the start value 0.5, not a random number. Now all hidden units calculate the same value and get the same gradient. Thus, they stay the same at all times. The network then works as if it has only one hidden unit, and it cannot solve XOR. Random start values break this symmetry. See <a href="#initialization">Why the starting weights matter</a>.

== 6ca8e0f3
A network with one hidden layer can approximate any continuous function on a bounded region as accurately as you want, if it has sufficient hidden units. Cybenko (1989) proved this for sigmoids. Leshno, Lin, Pinkus and Schocken (1993) proved it for each continuous activation that is not a polynomial. People often say that this theorem means "neural networks can learn anything". This is not correct. The theorem does not tell you <b>how many</b> units are necessary (possibly an extremely large number). It does not tell you if <b>gradient descent</b> will find the weights. It also does not tell you how well the result <b>generalizes</b> from a finite training set. In practice, depth is part of the answer: a deep network can represent some functions with few units, but a shallow network needs exponentially many units for them.

# Extra: end-to-end learning, then and now.

== 85214bd4
The networks of this week learn their own features. Examples are the hidden units of the digit network, the filters of a <a href="#cnn">convolutional network</a> and the <a href="#embeddings">embeddings</a> of words. This is <b>representation learning</b>. People often name it together with a second idea, <b>end-to-end learning</b>, and they say that these are the two key ideas of deep learning. This section explains the second idea. It also shows how this idea changed speech recognition, vision and translation, and how people use it today.

== f456864c
A system learns <b>end to end</b> when one model changes the raw input into the output that the task needs. The raw input can be pixels, the samples of a sound wave or characters. We train all the parameters of the model together, to make one loss on that output as small as possible. <a href="#backprop">Backpropagation</a> sends the gradient of that loss back through each layer, to the first layer. Thus, the needs of the last layer also change the first features.

== 75a3cab5
The alternative is a <b>pipeline</b>: a chain of stages. People design each stage by hand, or train it separately, with a goal of its own. Usually, experts designed the features of the first stage. Examples are histograms of edge directions for images (HOG, SIFT), coefficients that copy human hearing for sound (MFCCs), and counts of selected words for text. Then a classifier learned from the data that these features kept. Each stage can be good at its own goal. But it can also remove information that a later stage needs.

== 32f91142
Speech recognition shows both. Until the early 2010s, a speech recognizer was a pipeline with these parts: MFCC features; an acoustic model, which tells how each speech sound looks in these features (hidden Markov models with Gaussian mixtures); a pronunciation dictionary that experts wrote; a language model that learned from text; and a decoder that found the most probable sentence. Each part had its own data, its own goal and its own experts. From 2014, end-to-end recognizers (<a href="https://proceedings.mlr.press/v32/graves14.html" target="_blank" rel="noopener">Graves and Jaitly</a>, and Deep Speech) use one network. This network changes the sound, as a spectrogram, into characters. Whisper (2022) changes 30 seconds of audio into text with one Transformer. It learned from 680,000 hours of audio with transcripts.

== 6c8c3e7e
Representation learning says that a model can learn its features, and that people do not have to design them. End-to-end learning says what the features are for: the final goal, together with all other parts. A network is a composition of differentiable functions. Thus, one loss can train all of them at the same time. An <a href="#autoencoders">autoencoder</a> also learns a representation, but for a different goal: it must make its input again. If a separate classifier then uses the code of the autoencoder, the system is again a pipeline with two stages. Then it is a matter of chance if the code keeps the information that the classifier needs.

== d7611164
The figure below shows the difference in the smallest possible example. Each interface between two stages is a bottleneck: a later stage sees only the data that an earlier stage sends. Here the bottleneck is one number. We replace each point <span class="math">x</span> of the plane with its position <span class="math">z = w \cdot x</span> along a line. Then a <a href="../week3/#logistic-regression">logistic regression</a> classifier decides from <span class="math">z</span> only. The pipeline selects the line without the labels. It uses the direction in which the points change the most. This direction is the <b>first principal component</b>. One number along this line keeps more of each point than one number along a different line. This is a good goal if you want to make the data smaller, but it is not the goal of the task. The end-to-end model starts at the end of the pipeline, with the same line and the same classifier. Then it trains the line and the classifier together, with the loss of the classifier.

== c6e6a0ce
We change each point into one number <span class="math">z</span>: its position along a line. A classifier <span class="math">p = \sigma(a z + b)</span> then decides from <span class="math">z</span> only. The pipeline (dashed line) uses the first principal component, and it trains only <span class="math">a</span> and <span class="math">b</span>. <b>Train end to end</b> uses gradient descent on the mean log-loss to train the direction of the line and the classifier together (solid line). The strips show <span class="math">z</span> for each point, with class 0 at the top and class 1 at the bottom, and the threshold of the classifier. A ring shows a point with an incorrect class. If the classes are different across the cloud, the classifier needs the direction that the pipeline removes. If the classes are different along the cloud, the goal of the pipeline agrees with the task, and the two methods are equally good.

<b>Images.</b> In 2012, AlexNet won the ImageNet competition. AlexNet is a convolutional network that learned its features from the pixels. Its top-5 error was 15%. The best system with designed features had an error of 26%. By 2014, all the best entries were convolutional networks.

== 62435011
<b>Speech.</b> End-to-end recognizers are now the standard, for example in voice assistants and for the subtitles of videos.

== 6d0fe1f5
<b>Driving.</b> In 2016, NVIDIA trained a convolutional network that changes the image from a front camera directly into a steering angle. The network learned from human drivers. Nobody wrote lane detection or path planning into it.

== 2cb20135
Each time, the reasons are the same. No interface that people made removes information. A stage cannot send an error to a later stage that did not learn to correct it. And we optimize the system for the real measure of success, not for a different goal that people selected. Rich Sutton calls the general lesson of 70 years of AI research <i>the bitter lesson</i>: again and again, general methods that use more computation were better than methods that contain human knowledge.

<b>Data.</b> A model without built-in knowledge must learn everything from examples. Thus, end-to-end training needs many input–output pairs. If there are only a few pairs, a pipeline that contains the knowledge of experts can be better.

Explainability (<a href="../week7/">Week 7</a>) is more difficult for one large model than for a chain of small parts that people understand.

<b>Reuse.</b> You can use a stage of a pipeline again, for example a speech recognizer or a parser, and you can make it better on its own. We train an end-to-end model for one task. The alternative is to train it for many tasks at the same time. This is the idea of the foundation models below.

== 1597246b
The core material describes what each method calculates. This section asks what the calculation costs. How do time and memory increase with the size of the data and of the model? Why can the same arithmetic run ten or a hundred times faster when we arrange it differently? We count <b>multiply–accumulate operations</b> (MACs) and bytes. One MAC is two floating-point operations (FLOPs). Notation: <span class="math">N</span> training examples, mini-batches of <span class="math">B</span> examples, <span class="math">P</span> parameters and <span class="math">E</span> epochs.

== 16a5f11c
A dense layer with <span class="math">n</span> inputs and <span class="math">m</span> outputs has <span class="math">mn + m</span> parameters. For one example, it needs <span class="math">mn</span> MACs. For a mini-batch, the inputs are the rows of a matrix <span class="math">X</span>, and the full batch is one matrix product:

== 6c6993cc

The backward pass costs about two times as much, because each layer calculates two products of the same size. These are the gradient for its input, <span class="math">G W</span>, and the gradient for its weights, <span class="math">G^\top X</span>. Here <span class="math">G</span> contains the derivatives of the loss with respect to <span class="math">Z</span>. == 789d1ebf
The batch size is not in the formula. It changes the number of updates (<span class="math">N/B</span> in each epoch) and how efficiently the hardware works. It does not change the quantity of arithmetic. The digit network of the core material has <span class="math">P = 31{,}810</span>. Thus, one training step costs about <span class="math">6P \approx 191{,}000</span> FLOPs for each image. The 8 epochs over the 6,400 training images of the exercise need about <span class="math">9.8 \cdot 10^{9}</span> FLOPs. One modern CPU core with vector instructions can do approximately <span class="math">10^{11}</span> FLOPs each second. An example is 3 GHz × 2 fused multiply–add units × 8 single-precision lanes × 2 FLOPs. Thus, the arithmetic alone takes about 0.1 seconds. Real code takes more time: small matrices, memory traffic and the Python interpreter add overhead. Performance engineering decreases this difference.

== 6a12dab0
<b>Memory.</b> Training keeps four types of numbers. These are the <span class="math">P</span> parameters, their <span class="math">P</span> gradients, the state of the optimizer and the <b>activations</b> of each layer. The optimizer state is zero for plain SGD, <span class="math">P</span> for momentum and <span class="math">2P</span> for Adam. The backward pass needs the activations: <span class="math">B \sum_\ell n_\ell</span> values for the layer widths <span class="math">n_\ell</span>, with the input. Prediction needs only the parameters and the activations of the current layer. In the digit network, the parameters use 127 KB as 32-bit floats. This is small enough to stay in the cache of a CPU core. The activations of a batch of 200 images use 0.67 MB.

== 415fce31
<b>Performance: select the number format.</b> The 70,000 MNIST images use 439 MB as 64-bit floats, which <code>fetch_openml</code> gives. As 32-bit floats they use 220 MB, and as bytes 55 MB. Thus, the exercise changes them with <code>astype("float32")</code>. This halves the memory traffic, and each vector instruction holds two times as many numbers (8, not 4, in a 256-bit AVX2 register). Neural networks rarely need 64-bit precision. GPUs go further: they train with 16-bit formats (see the checklist below).

== 392639e9
A processor can calculate only as fast as it gets the data. The <b>arithmetic intensity</b> of a calculation is the number of FLOPs for each byte that it moves to or from memory. A matrix–vector product, with one example at a time, uses each weight one time: 2 FLOPs for each weight. With 16-bit weights, this is about 1 FLOP for each byte. A mini-batch of <span class="math">B</span> examples uses each weight <span class="math">B</span> times, so the intensity increases with <span class="math">B</span>. The <b>roofline model</b> changes this into a speed limit:

Below the ridge point (here 100 FLOP for each byte), a calculation is <b>memory-bound</b>. Then faster arithmetic does not help. Only less data movement helps. Above the ridge point, the calculation is <b>compute-bound</b>. Matrix libraries (BLAS on CPUs, cuBLAS on NVIDIA GPUs) get near the peak. They divide the matrices into tiles that stay in the registers and caches while the library uses them again. You can see the effect on a laptop:

== e7129f8a
A perceptron prediction costs <span class="math">O(d)</span> for <span class="math">d</span> inputs. Thus, one epoch costs <span class="math">O(Nd)</span> time, and <span class="math">O(d)</span> memory in addition to the data. How many epochs are necessary? The convergence theorem (Novikoff, 1962) gives the answer from the geometry of the data. Use the labels −1 and +1, and a constant input 1 for the bias. Let each input have <span class="math">\lVert x \rVert \le R</span>. Let a unit vector <span class="math">u</span> separate the classes with the margin <span class="math">\gamma</span>: <span class="math">y\, u \cdot x \ge \gamma</span> for each example. Then the perceptron makes a maximum of

== d421e47f
Each epoch before convergence has one or more mistakes. Thus, training takes a maximum of <span class="math">(R/\gamma)^2 + 1</span> epochs and <span class="math">O\bigl(Nd\,(R/\gamma)^2\bigr)</span> time. When the classes are separable but almost touch, the margin is small, and training can need many epochs. For XOR, there is no margin, and the bound gives no information.

== 0746c528
<b>Performance: vectorize the independent work.</b> Each perceptron update changes the weights that the next example uses. Thus, the loop over the examples must go in sequence. Only the dot product in each step can use vector instructions. A mini-batch gradient step is different: all <span class="math">B</span> examples use the same weights, so one matrix product gives all their gradients. When you must use a loop in sequence, run it as compiled code (C++, Numba or <code>jax.lax.scan</code>), not in the Python interpreter. In the interpreter, each iteration costs much more than its arithmetic.

== 245b1dbb
The 16 RGB filters of size 3 × 3 in the core material have 448 parameters. On a 32 × 32 image with padding 1, they do <span class="math">32 \cdot 32 \cdot 16 \cdot 27 = 442{,}368</span> MACs. This is about 1,000 for each parameter. A dense layer uses each weight only one time for each example. This high arithmetic intensity is one reason why CNNs run well on GPUs. == 81f74e57
<b>Performance: one operation, different algorithms.</b> Libraries implement a convolution in different ways. <i>im2col</i> copies each patch into a column of a matrix and then uses a fast matrix product. But the copied input needs about <span class="math">k^2</span> times more memory (Chellapilla et al., 2006). Winograd's minimal filtering calculates a 2 × 2 block of outputs of a 3 × 3 filter with 16 multiplications, not 36: 2.25 times fewer (Lavin and Gray, 2016). Methods with the FFT are good for large filters. On NVIDIA GPUs, cuDNN selects one of these algorithms for each layer shape. In PyTorch, <code>torch.backends.cudnn.benchmark = True</code> lets cuDNN measure the time of each algorithm one time and keep the fastest. The memory layout is also important. "Channels last" (NHWC) keeps the channels of one pixel next to each other. This is good for vector instructions and tensor cores.

== 1cff97da
An embedding lookup copies one row of the table: <span class="math">O(d)</span> for each token. A one-hot vector times the table gives the same result, but it costs <span class="math">O(Vd)</span>. The table can be the largest part of a model, for example in recommender systems. The backward pass changes only the rows of the tokens in the batch. To find the nearest neighbours of one vector among <span class="math">V</span> vectors costs <span class="math">O(Vd)</span>. Normalize the table one time. Then one matrix–vector product gives all cosine similarities. For millions of vectors, approximate nearest-neighbour indexes such as HNSW (Malkov and Yashunin, 2020) are much faster, but a little less accurate. Vector databases use these indexes.

== 44df6543
A recurrent step <span class="math">h_t = \tanh(W_x x_t + W_h h_{t-1} + b)</span> costs <span class="math">d_h (d_x + d_h)</span> MACs. Thus, a sequence of length <span class="math">T</span> costs <span class="math">O\bigl(T d_h (d_x + d_h)\bigr)</span> time. Training keeps all <span class="math">T</span> hidden states: <span class="math">O(T d_h)</span> memory for each sequence. <b>Performance:</b> the steps cannot run in parallel, because step <span class="math">t</span> needs <span class="math">h_{t-1}</span>. Only the sequences of a batch can run in parallel. Attention in Week 5 removes this dependency and processes all positions at the same time. But it must compare each pair of positions: <span class="math">O(T^2)</span> parallel work, not <span class="math">T</span> steps in sequence.

== 7d60e116
<b>Measure first.</b> Profile before you optimize: <code>cProfile</code> or py-spy for Python, <code>torch.profiler</code> for PyTorch, Nsight Systems for NVIDIA GPUs. Frequently, the slow part is not where you expect it.

== ab2779c9
<b>Find the limit.</b> Compare the FLOP/s that you get with the peak. Also compare the bytes per second that you get with the memory bandwidth. A memory-bound calculation needs less data movement, not faster arithmetic.

== fef15ffe
<b>Use smaller number formats.</b> On CPUs, use 32-bit floats, not 64-bit floats. On GPUs, mixed precision calculates with 16-bit formats on tensor cores and adds the results in 32 bits (Micikevicius et al., 2018). bfloat16 has the same exponent range as 32-bit floats. float16 needs loss scaling, so that small gradients do not become zero.

== 752f145f
<b>Use good shapes.</b> Tensor cores work best when the matrix dimensions are multiples of 8 for 16-bit numbers. Larger multiples frequently help more.

== 6d8c138c
<b>Keep the device busy.</b> While the current batch trains, load and preprocess the next batches in background workers. A GPU that waits for data shows low utilization.

== 4a72769a
<b>Use more computation to save memory.</b> Gradient checkpointing keeps the activations of only some layers. It calculates the other activations again during the backward pass. It keeps about <span class="math">\sqrt{L}</span> layers, not <span class="math">L</span>, and it needs about one more forward pass (Chen et al., 2016).

== 797aec02
<b>Fuse small operations.</b> A chain of element-wise operations is memory-bound when each operation reads and writes a full tensor. Compilers such as <code>torch.compile</code> and XLA fuse them into one pass.
